# Changelog

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

While the major version is 0, breaking changes can land in any release.

## [0.1.0] - 2026-08-24

First public release. The pipeline works end to end on real sessions: read a
Claude Code transcript, archive it losslessly, extract typed state with a model,
package it as a portable `.ctx`, validate it, and compile it into context for
five provider families.

**The compaction thesis remains unproven**, and the benchmark saying so ships
with the code rather than being left out of it.

### Added

- Phase 13. Open Source V1 finalisation.
  - `CODE_OF_CONDUCT.md` — Contributor Covenant 2.1, unmodified, with reporting directed through GitHub rather than a personal address.
  - `CONTRIBUTING.md` gains three sections it lacked: **where compaction strategies live and how they are evaluated** (including why a benchmark regression is a reason to stop rather than a number to adjust), **the benchmark methodology** (four arms, retention and continuation kept as separate measures, judged questions asserting absence while deterministic checks assert presence, the judge calibrated against the reference arm, and run fingerprints that include the repetition index), and **the free-models-only policy** — stated explicitly as a policy for *this repository's own testing*, not a limitation on anyone using the software.
  - `SECURITY.md` gains the sections it predated: a `.ctx` package as untrusted input, the no-execution rule and the test that enforces it, `archive.location` never being resolved, what `validate` reports and what it explicitly does not claim, and credential handling.
  - `THIRD_PARTY_NOTICES.md` now lists `pydantic-core`, which ships with `pydantic` and was unlisted. Every licence was read from the installed package metadata rather than from memory; all are MIT and compatible with Apache-2.0.
  - README test count corrected (1,228 to 1,285) and pointers added to the Code of Conduct and Security policy. Every CLI command the README names was checked to exist; all 102 internal documentation links resolve.
  - **Phase 8 remains PARTIAL, and the roadmap now says so in those words.** The implementation exists and is tested; its *measurement* exit criterion is unmet because the arm could not be evaluated on the only model with the daily allowance to run the full matrix. That is a research limitation, not an engineering one, and the distinction is recorded rather than smoothed over.

### Fixed

- Phase 5.7. The reasoning registry said things nobody had checked, and the one test that would have caught it had never run.
  - **Five OpenRouter entries claimed `Reasoning.NONE` without ever being called.** Three of them reason: `nvidia/nemotron-3-nano-30b-a3b:free` (44 reasoning tokens on a trivial prompt), `liquid/lfm-2.5-2.6b:free` (78), and `nvidia/nemotron-3-super-120b-a12b:free` (91). `check_output_cap` had therefore been silently inert for that provider since the day it was added — the two `google/gemma-4` entries were right, but by luck rather than by measurement. All five have now been called and carry the date they were seen.
  - **The default was the dangerous one.** `Reasoning` defaulted to `NONE`, the single value that disables the check, so an entry added without measurement disabled the gate for itself. It now defaults to `UNKNOWN`, which is given the full reasoning floor: assuming a direct model reasons costs some output budget, while assuming a reasoning model answers directly returns an empty completion, and only one of those is safe to get wrong.
  - **`reasoning_measured_on` separates an observation from a belief.** A value without a date does not count as measured, and `reasoning_measured` says so. The enum's docstring claimed every value had been measured against the live endpoint while five had not; it now states the rule it actually keeps.
  - **`test_real_provider_smoke.py` failed on every run where a credential existed**, and had been skipped for so long that nobody noticed. Its flat `max_output_tokens=300` fell inside the 512-token floor of every approved Groq model, so the request was refused before it was sent. The budget is now derived from `reasoning_overhead`, so the test and the gate agree by construction and a changed floor moves both.
  - **Only a rate limit is transient.** A shared free tier throttles without warning, and failing a suite over somebody else's traffic makes a green run depend on strangers. A 429 now skips with its reason; an authentication failure, a vanished model, a refused request, or a malformed response all still fail, using the error taxonomy the provider layer already had rather than matching on message strings.
  - **Both providers now pass against real free models** — Groq on `openai/gpt-oss-20b`, OpenRouter on `liquid/lfm-2.5-2.6b:free`. No paid model was called and no paid fallback exists: an unapproved model is refused before any HTTP request.
  - 17 new tests, 9 of which run without a network so the smoke test's contract cannot rot again while it is being skipped.

### Added

- V2.4. The compiler can now retrieve evidence from the local archive.
  - `compile_context(..., archive=...)` with `CompilationRequest.retrieve`, and `open-context compile --retrieve N --archive DIR`. Off by default: a package that arrived from another machine has no archive to search, so a caller who does not ask gets exactly the behaviour they had before.
  - **Built against a measurement.** The adversarial benchmark found that what compaction loses is exact values, and that all of its loss sat in the two scenarios built around them. A summary cannot keep every number; the archive still holds them.
  - **Measured**: on four scenarios drawn from those failures, the answer appeared in **0 of 4** compiled contexts without retrieval and **3 of 4** with, at **+28% tokens**.
  - **The miss is documented rather than smoothed over.** Asked "what encoding should the export writer use", lexical retrieval cannot find "the downstream loader rejects UTF-8; write UTF-16LE with a BOM" — after stopwords the two share no words at all. That is the structural limit of lexical matching, and it is the case that would justify examining embeddings under the roadmap's rule. One in four, with the failure understood, is not a reason to add a vector database.
  - **The archive is streamed, never loaded.** Records pass a bounded heap, so searching 80,000 costs what searching ten does — pinned by a test that counts every record consumed and measures the memory taken.
  - **Provenance travels with the text.** Every retrieved line carries the record id it came from, under a heading naming the archive as its origin: a record cited without saying which record it was is an assertion, not evidence.
  - Budgeted like any other section and dropped before the session's own state when the budget is short. Deterministic — ties resolve by archive position, so the same inputs give the same context even when records arrive in a different order. Records the package already quotes are suppressed. A failing archive produces a warning and a context without the extra records, because that context is smaller rather than wrong.
  - 26 new tests.

- Extraction that works on a real session, and a re-verified free-model registry.
  - **The allowlist had gone stale in ten days, and re-verifying found it.** `openai/gpt-oss-20b:free` **stopped being free** on OpenRouter — an allowlist naming a model that now costs money is the exact failure it exists to prevent. Both Groq llama models **vanished from the account**, taking every non-reasoning chat model with them: as of 2026-08-23 every general model reachable there reasons before it answers, so `check_output_cap` is no longer an edge case. `open-context verify-models` re-checks the registry against the live catalogues, exits non-zero when an approved model is priced, and reports a vanished one without failing — it cannot be called, so it cannot bill.
  - **`--extract` was entirely non-functional.** Providers register themselves on import and the CLI never imported them, so every run failed with "no provider registered as 'groq'". The design is right — the abstraction stays network-free and a caller wanting a real model imports the providers on purpose — but the CLI *is* such a caller and had not said so.
  - **One-shot extraction does not fit a real session.** The first live run offered 19,178 tokens to a model with an 8,000-per-minute ceiling and was refused with HTTP 413. `extract_windowed` reads the session in windows small enough to send, each carrying the state found so far — because a window that saw only its own messages has never seen the decision being overturned in a later one, which is what Phase 7 measured before `known_state` existed. Windows cut on record boundaries: half a tool result is a different tool result.
  - **Rate limits are now waited out, because the provider says how long.** `RateLimitError.retry_after` has been carried since Phase 4.5 and deliberately never acted on — the boundary refuses to pick a retry policy for its callers — and windowed extraction is a caller. Without it, a live run had **32 of 35 windows** refused while being told the exact seconds that would have fixed each. With it: **19 items and 11 failed windows**, up from 3 and 32. Bounded at three attempts and 30 seconds per window, because a provider asking for ten minutes is saying come back later and a tool that obeyed silently would look hung.
  - **A failing window does not fail the session**, and a partial extraction says so — the incompleteness is invisible in the state itself, since nine correct facts look identical whether or not there were twelve. The watermark does not advance on a partial read.
  - **Provenance survived the unwrapping.** Phase 6 put archive ids on the `ExtractedItem` wrapper rather than on `sources`, so the first windowed implementation dropped them and every package reported "19 of 19 state items have no archive provenance". Carried alongside now: a live extraction produces `traced 9 of 9` and validates at provenance depth.
  - **A boundary test caught an architectural violation as it was written**: the first `verify` module imported `urllib` from inside `open_context.llm`, where the abstraction is network-free by construction. It lives under `providers/` now, where reaching a real service belongs.
  - 20 new tests.

- V2.3. Hierarchical context: project, session, event.
  - `src/open_context/hierarchy.py`, `CtxPackage.inherited`, and a compiled `INHERITED` section. A session now receives what earlier sessions on the same project established.
  - **The logical model only.** Three levels and a parent link — a dictionary. A test asserts the module reaches for no storage engine, because the roadmap is explicit that a graph-shaped model is not a reason to install a graph engine.
  - **A project is a repository root, not a working directory**, and real data settled it: of six measured sessions, two ran in `open-context` and `open-context/files (4)/open-context-runtime 2`, which is one project and a directory inside it. Splitting them hides a session's own history from itself. Identity resolves through `.git`/`.hg`/`.svn` by looking at the filesystem, never by parsing a path for something that resembles a project name. On this machine none of the six directories is a repository, so each is correctly its own project, and the merging behaviour is verified against a real marker rather than asserted.
  - **No TASK level**, though the roadmap sketches one: nothing in a real transcript marks where one task ends, so the boundary would have to be inferred, and an invented boundary looks exactly like an observed one.
  - **Inherited state is labelled, never merged.** The builder refuses foreign state because mixing sessions would present one agent's work as another's — that guard is right, so inherited context got its own field rather than a weaker check. It compiles under a heading naming its origin: "we decided X" and "another session decided X" are both worth carrying and are not the same sentence. When the budget is short it is dropped before the session's own state.
  - **Two bugs, both caught by tests, both from bolting a feature onto an invariant instead of respecting it.** Carried state was merged into `state` and correctly rejected. And sibling lookup leaked between unrelated projects, because nothing recorded which project a stored session belonged to — a constraint from an unrelated project reached a package before `StoredState` began carrying its `project_root`.
  - 22 new tests.

- V2.2. Incremental compaction: extract what arrived since last time.
  - `src/open_context/incremental_store.py` and incremental `extract_state`, on by default.
  - **Phase 7 built the machinery and nothing called it.** `Watermark`, `extract_incremental`, and `reconcile` all existed, yet every package re-read the whole archive and paid a model for the whole conversation again — a session repackaged ten times paid for its first turn ten times. The missing half was somewhere to keep the watermark between runs.
  - **Measured**: a session grown to 200 turns in batches and repackaged after each — 199,110 prompt characters and 15.4 ms full, against 75,802 and 4.6 ms incremental. **62% and 70%**, with the same state kept. The shape matters more: the incremental prompt stays flat at ~15,000 characters while a full read climbs to 64,926, so cost tracks new events rather than total ones and the saving widens with session length.
  - **Stated caveat**: the numbers come from a counting stand-in, not a real model. That is the right instrument for how much work is *sent*, and it says nothing about whether a real model finds the same things from a partial view.
  - **The prompt carries known state as well as new events**, which is why a second run is not smaller than the first — only smaller than re-reading everything. Phase 7 paid for that lesson: a model shown only new messages has never seen the decision being overturned and reports a reversal that resolves to nothing.
  - **State and watermark are written together, atomically.** Stored apart, a crash could leave a watermark claiming events had been read beside state that never saw them, and nothing downstream could detect the gap. A damaged file reads as "nothing known" — recovery rather than a permanent failure — and a file naming another session is ignored, since adopting it would attribute one conversation's decisions to another.
  - The watermark advances only on success, so a rate-limited or malformed extraction leaves the range to be read next time rather than skipped silently.
  - 12 new tests.

- V2.1. Automatic capture when an agent hits context pressure.
  - `src/open_context/pressure.py` and `open-context hook`. Wired into Claude Code's `PreCompact` hook, it writes a validated `.ctx` at the moment the agent decides its window is full.
  - **The mechanism was verified against the shipping binary before a line was written**, which this phase requires in terms. Claude Code 2.1.195 emits `PreCompact` *before* compacting, carrying `session_id`, `transcript_path`, `cwd`, and `trigger`, where `trigger: "auto"` means the agent decided by itself. The timing is the whole value: after compaction the detail is gone, so a hook firing before is the difference between capturing a session and capturing a summary of one.
  - **It never blocks compaction, though the protocol allows it.** The binary carries the string *"Compaction blocked by PreCompact hook; continuing uncompacted"*, so a `decision` in the response would stop the agent. A test asserts the handler never votes: a context tool able to silently prevent an agent from compacting could run a session out of its window, and a user debugging that would have no reason to suspect the thing they installed to help.
  - **It never fails the hook.** The response says `continue` whatever happened and the command exits 0 even when it captured nothing, because a non-zero exit is how a hook tells an agent something is wrong and a failed backup is not that. A malformed or unrecognised payload is handled rather than raised — the payload comes from another program that may add or rename fields, and breaking the user's agent to report our own confusion is the wrong trade.
  - **Manual compactions are ignored by default.** A user who typed `/compact` has decided what they want; capturing anyway asserts the tool knows better and doubles what a session costs on disk. Transcripts under 4 KB are skipped for the same reason — a directory of near-empty packages is how a useful feature becomes one people turn off.
  - Measured on a real transcript: 303 events captured into a 4.4 KB package that validates at provenance depth.
  - 12 new tests.

- Phase 13. Open Source V1: a stranger can install this and use it.
  - **Exit criterion met against a built wheel in a fresh virtualenv, outside the repository** — not an editable development install, which is the one thing a release gate exists to distrust. All ten steps verified: clone, install, understand, import a conversation, compact it, generate a `.ctx`, inspect it, validate it, compile it for another agent, continue the work. `pytest`, `ruff check`, `ruff format --check`, and `mypy` all clean.
  - **Two problems appeared only once the wheel was installed elsewhere.** There was no console script, so a user had to know to type `python -m open_context`; `open-context` is now an entry point. And the CLI help was written for the author — it cited phase numbers a stranger has no reason to know — so it now describes what the commands do.
  - **Two product gaps surfaced from running the stranger's own workflow.** A single long assistant turn spent 476 of a 500-token budget and pushed ten other turns out of the recent window, so turns are clipped to 1,200 characters with the clipping marked — breadth is what a recent window is for. And a package built without extraction carries no state at all, which undersells the artifact: `--extract` now wires the extractor into `handoff`, opt-in because it is the only step needing a model, and running **after** archiving so a failed call costs the call rather than the conversation.
  - **A warning-clobbering bug, caught by the test written for it**: `handoff` replaced its warning list with the packaging step's, so a failed extraction reported nothing at all. Warnings are now extended, never replaced.
  - `docs/getting-started.md` and a documentation index. The nine topics the roadmap names are covered by files already carrying clearer titles — `ctx-format`, `hardening`, `handoff`, `llm` — so the index maps topic to file rather than fragmenting the docs into stubs of the same material.
  - **The README states the negative result in its status block.** The compaction thesis is unproven on this project's own adversarial benchmark, and that belongs above the fold: a benchmark published only when it agrees with you is not a benchmark. The one unsupported number in the README — a package "5k to 20k tokens" — was replaced with the measurement: 13.7 KB from a 24.8 MB session, 0.055% of the source.
  - `THIRD_PARTY_NOTICES.md` corrected: it claimed an empty dependency list, which stopped being true when pydantic became a runtime dependency.
  - 4 new tests.

- Phase 12. Production hardening: what happens when the input is hostile, damaged, or very large.
  - `src/open_context/package/security.py` — `review()` reports what a package carries; `validate` prints it. Plus a provenance frame in the compiler, streaming archive description, a two-pass session survey, and a state-schema version in the manifest.
  - **A `.ctx` is untrusted input by design**, and the roadmap's hard rule is kept by construction: nothing executes anything because it appeared in imported context. No `eval`, no shell, no dynamic import, no path resolution anywhere a package can reach — asserted by parsing those modules, so it survives a later edit rather than resting on having been careful once. `archive.location` is carried verbatim and never opened; `/etc/passwd` and `../../../../etc/shadow` are strings.
  - **Injection is reported, never claimed to be removed.** It cannot be detected reliably, and a function that stripped the dangerous parts would make a promise it cannot keep — leaving a caller who believed it worse off than one who knew. A clean review prints *"nothing remarked on (which is not a guarantee of safety)"*, because a report implying safety would itself be the vulnerability. The pattern list is short on purpose: a check that fires on ordinary engineering conversation stops being read.
  - **The compiler now says where its content came from.** In a system prompt "the constraint we agreed" and "an instruction to you" are indistinguishable unless the model is told which it is reading. Every compiled context opens with a line stating the content is a record of earlier work, not instructions — budgeted like any other section, because a mitigation that arrived free would mean the token accounting was wrong, and warned about rather than dropped when the budget cannot hold it.
  - **Describing an archive no longer reads it.** Building a package needs an archive's shape and the few records its state cites; the first version called `list()` on the whole thing, which is precisely the proportional cost the archive exists to avoid. Streaming removed ~80 MB on a 25 MB transcript.
  - **Branch resolution no longer holds the conversation.** Resolving rewinds needs every turn's identity and nothing else, so the survey drops text on the first pass and re-reads for the few turns actually carried: 51 MB to 27 MB, most of the difference tool output nothing downstream reads.
  - **Fixed a silent detection bug found while testing.** Detection sampled a fixed 8 KB prefix, but one JSON Lines record can be 1.36 MB. A first record longer than the sample arrived cut in half, the Claude Code check read that as "not my format", and the generic reader — which accepts anything shaped like JSON — claimed the file. The result would have been a successful-looking import of a session as anonymous records, losing tool calls, the parent chain, and the branch structure. Detection now samples whole lines, with a byte ceiling.
  - `manifest.state_schema_version`, checked separately from `format_version` and re-exported from the storage schema so the two cannot drift. A package this code can open but whose state it cannot read is a specific, fixable situation; reporting it as an unreadable package would send a reader looking in the wrong place.
  - Measured on a real 24.8 MB transcript: 1.0 s wall, 34 MB fixed import overhead, a 13.7 KB package — 0.055% of the source.
  - 29 new tests.

- Phase 11. Reading a real coding agent's sessions, and handing one to a different agent.
  - `src/open_context/importers/claude_code.py` and `src/open_context/handoff.py`, plus `handoff` and `sessions` CLI verbs. The whole workflow runs: `sessions` -> `handoff` -> `validate` -> `compile`, verified on this machine's own transcripts.
  - **The format was inspected rather than assumed**, which the roadmap asks for in terms. Six real transcripts, 8,890 conversation records. Three findings, each contradicting the obvious reading.
  - **A session file is a graph, not a list.** Records carry `uuid`/`parentUuid`, and 5 of the 6 files had a parent with several children — rewinds and retries whose abandoned attempts stay on disk. Read top to bottom, a transcript yields work that was taken back, presented as though it happened.
  - **The parent chain runs through records that are not conversation**: 804 attachment and 62 system records sit between turns in one session alone, so `parentUuid` usually points at an attachment. Events now carry `conversation_parent` — the nearest ancestor that is actually a turn — while `parent_id` stays verbatim, because a derived value in a field documented as verbatim is a quiet lie.
  - **A second root is a continuation, not a rival, and getting this wrong destroyed most of two sessions.** Claude Code starts a *new tree* when it compacts; measured on two long transcripts the trees are strictly sequential, splitting exactly at the `isCompactSummary` record — 2,407 then 388, and 3,294 then 927. The first `active_thread` kept only the chain ending at the last record, which is the obvious reading of a DAG, and discarded **78% and 86%** of those sessions: every pre-compaction turn, precisely the history a handoff exists to carry. One of the two files contains no forks at all, so nothing about it was ambiguous — only real data showed the error. Forks are now resolved; roots are kept.
  - **Thinking blocks are skipped by default.** They are deliberation, not answers, and this project has already stored one as the other — `strip_inline_reasoning` exists because a compactor saved a truncated `<think>` block as a summary. A turn that was only thinking still yields an empty event, so the chain keeps a link where a turn occurred.
  - One record can produce several events. A turn with text and three tool calls is four things that happened, and collapsing them loses the tool calls, which Phase 8.5 measured to be where answers hide.
  - **Registry order is load-bearing.** `JsonLinesImporter.detect` accepts any line that parses as a JSON object, which every transcript also does, so a generic-first registry would claim every session file and import it as anonymous records — losing tool calls, the chain, and the branch structure, while appearing to succeed. `importers/registry.py` puts specific formats first and exists as its own module because a registry naming both would make `generic` import `claude_code`, which already imports it.
  - **The adapter decides nothing**, per the roadmap's rule: it reads, archives, and packages, leaving selection to the compactor and budgeting to the compiler. The archive is written **before** anything is interpreted, so a failed extraction costs the expensive step rather than the conversation. Malformed records are skipped here rather than aborting, because a live session file can have a torn tail simply because the agent writing it is still running.
  - **State is passed in, not extracted.** Without it the package carries recent context and provenance and says so in a warning, which is a smaller claim honestly made rather than a larger one faked. Recent context excludes tool traffic: it is 3,082 of 8,890 records, and a window full of shell invocations tells a receiving agent less than the same budget spent on what was said.
  - 32 new tests.

- Phase 10. The context compiler: a provider-neutral `.ctx` turned into context a specific agent can use.
  - `src/open_context/compiler/`: `compile_context` selects and budgets on a provider-neutral structure; `render_for` shapes the result into one family's request format. `python -m open_context compile … --target anthropic --budget 2000`.
  - **Exit criterion met**: the same package compiles to useful context for `openai`, `anthropic`, `gemini`, `local`, and `generic`, each in that family's own shape, proven from a file on disk.
  - **The portable layer decides; targets only render**, and that is enforced by what a renderer is handed rather than by convention. A renderer takes one argument — an already-selected, already-budgeted context with no tokenizer and no budget — so it cannot drop, reorder, or re-fit anything even by accident. This is the roadmap's "do not duplicate compaction logic in adapters". The failure it prevents is quiet: five adapters each choosing what to include would become five slightly different compactors, the same `.ctx` would mean different things depending on where it was sent, and every one of them would still produce something that looked reasonable. Tested by inspecting the renderers' signatures and their imports, so a later change cannot loosen it silently.
  - **Fitting is imported, not reimplemented.** `fit_state` comes from the hybrid compactor unchanged, because the priority order deciding what survives a small budget was arrived at by a benchmark result and a second copy would drift from the first.
  - **Naming a target model changes nothing about what is compiled.** It is recorded so a compiled context can say what it was built for; a compiler that wrote different content per model would make the package's neutrality a fiction.
  - **An unknown target falls back to plain text rather than failing.** Refusing would make the format less portable than the text it is made of.
  - Sections are placed in priority order — task, state, evidence, recent — each given what the previous left. A task that does not fit is an error rather than a truncation: a context without its task is not a smaller context, it is a different one. Recent turns are taken from the **end**, since showing what was just happening is the section's only purpose. What was dropped is part of the result, not a log line.
  - `local` is a separate renderer rather than an alias for `openai`, because "a local model" is a deployment choice and not a promise about schemas.
  - The CLI counts with a word tokenizer and **labels the number estimated**. Counting exactly needs the target model's own tokenizer, and compiling a context is not a reason to make a network request.
  - 23 new tests, plus 2 covering the CLI.

- Phase 9. The portable `.ctx` package, and a CLI that generates, validates, and inspects one.
  - `src/open_context/package/`: `build` assembles a package from a session's state, `validate` checks one, `render` lays it out for a person. `python -m open_context pack | validate | inspect` does the same from a terminal, proven end to end against a real SQLite store and a real archive on disk.
  - **One JSON document, not a container.** A zip would carry the whole conversation cheaply and is rejected for that reason: *human-inspectable* is a requirement of the format, and a file you must unpack before reading does not meet it. A `.ctx` opens in an editor, diffs in a review, and survives being pasted into a bug report. The file is indented and key-sorted; the hash is over a canonical serialisation, so readability costs nothing.
  - **It references the archive rather than embedding it.** A package carrying its own copy of the history is a second copy that begins to diverge immediately, and the archive is already verifiable. The reference hashes only the records the package actually cites — hashing all of them would grow a pointer into a manifest of the whole conversation, hashing none would leave a receiver unable to tell one archive from another.
  - **Provenance that cannot be followed is still recorded.** Dropping an unresolvable reference destroys the only trail back to the source; marking it unresolvable costs one field and is true. `PackageBuildReport` carries the count so a caller deciding whether to hand the artifact to another agent learns it before doing so, rather than from a log line.
  - **A question Phase 6 left open was half-answered.** Phase 6 found that `StateItemBase.sources` speaks the SQLite `msg_`/`ev_` scheme while the archive numbers its records by sequence, and refused to invent a mapping. That refusal was right about *sequence numbers* and too broad about *ids*: `ArchiveRecord.id` is defined as "identity of the underlying item, preserved as given", so an archive fed the same messages already holds the very ids `sources` names. Resolving through them is a lookup on an identifier both sides agreed on. An explicit mapping still wins, and a source this archive does not hold still does not resolve.
  - **Validation has two depths and reports which it reached.** Structure alone, or structure against the archive. The dangerous case is a package that passes the first and fails the second — internally impeccable and describing a different archive — so the depth is part of the verdict, and the CLI says on stderr when it had no archive to check against. `validate` exits non-zero when invalid, and with a different non-zero code when the file could not be read as a package at all.
  - **A future version is refused rather than parsed.** A newer package may parse cleanly while a field has quietly changed meaning, and that failure is silent.
  - **Superseded items are excluded and the exclusion counted**, for the reason Phase 8 gave for not rendering them: a reader given both sides of a reversal without being told which won is worse off than one given neither.
  - The first working build hashed **no** archive records, because the cited set came from the caller's explicit mapping rather than from the evidence actually assembled — so a package built on inferred provenance cited records it never hashed, and the deep check would have passed for want of anything to fail on. Caught by looking at the artifact rather than the test suite, which was green.
  - `ids.PACKAGE` (`ctx_`), because a package id reading `ses_` is a lie in a scheme whose whole premise is that identifiers describe themselves.
  - 43 new tests.

- Phase 8.5 results, and two integrity checks the run earned.
  - **The benchmark discriminates.** 96 of 96 cells, `llama-3.1-8b-instant`, budget 160, three repetitions. The reference arm scores **1.000 with zero variance across all three** — the control Phases 5.8 and 8 never had. Everything the scenarios ask for is recoverable from the uncompacted conversation, so every point lost below is lost by compaction rather than by the model. Compaction costs **25–28%** at 9–14x compression against a within-arm spread of 0.167.
  - **The Phase 5 baseline still does not beat a plain summary**: 0.750 against 0.722, a gap of 0.028 inside noise of 0.167. Phase 5.8 found this on 220–385 token scenarios; it survives on scenarios six times longer at ten times the compression.
  - **All the loss is in two scenarios**, both built around exact values. The positional trio — the most carefully constructed part of `v4`, differing only in where the requirement sits — scores 1.00 for every arm. A negative result worth having: it rules out primacy and recency as an explanation for anything else measured here.

Its apparent 0.667 was the Phase 5 baseline wearing hybrid's name. Phase 8's bet is neither confirmed nor refuted; what is established is that **hybrid requires a model capable of structured extraction, and an 8B model is not one** — and the model with the daily token allowance to run the full matrix is the 8B one.

The warning had been in the results file since Phase 8 and nothing read it, so a composite strategy's fallback was being reported under the composite's name. On identical questions an 8B judge passed **9 of 24** where a 70B judge passed **8 of 8** — one representative failure marked a response wrong for "listing" an approach it had explicitly ruled out. `format_benchmark` now reports the judge as unreliable and says the judged scores must not be read.

Reading the headers and concluding there was no daily token limit is the mistake made here, and it is recorded as such: a limit absent from the telemetry is not a limit that is absent.

- Phase 7. State and retention management. Incremental update, supersession resolution, and deterministic conflict detection.
  - `src/open_context/state/`: `Watermark` and `extract_incremental` read only what has arrived since the last successful pass, `reconcile` folds an extraction into existing state, `detect_conflicts` finds structural contradictions.
  - **A watermark is earned, not assumed.** It advances only when an extraction over that range succeeded; one moved on a malformed reply would skip a region of the conversation permanently, with nothing downstream able to tell. It never moves backward — rewinding would make later events be extracted twice and reconciled against themselves — and an extraction that found nothing still advances it, because reading a range and finding no state is success.
  - Nothing new calls no model and returns `None` rather than an empty result. "Nothing was read" and "a range was read and yielded nothing" are different facts, and a caller unable to distinguish them could not tell a quiet session from a broken extractor.
  - **Old state is an input to extraction, which the first real incremental run proved by its absence.** It read one new event, produced a correct new decision and a correct new constraint, and linked neither to the decision they replaced: a model shown only the new messages has never seen the earlier decision and cannot name it, so the reversal became two orphaned assertions beside a still-active predecessor. `known_state` now renders current items into the prompt **verbatim**, since supersession is matched literally and a paraphrase resolves to nothing. The same conversation then produced `0 new, 0 unchanged, 1 superseding`.
  - **Reconciliation returns a plan, not an effect.** A caller inspects it, resolves what it cannot accept, and only then commits — which is what lets a conflicting update be refused rather than half-applied. Identity is type plus normalised content, not the id: ids are minted per extraction, so matching on them would make every re-run look like entirely new state. An item asserting a change is never filed as unchanged, whatever its content matches.
  - **Nothing is deleted.** `apply_supersession` returns both records — the old one marked superseded, keeping its content, rationale, sources, and timestamps, and the new one pointing at it. A retired decision that lost its reason would defeat the point of retaining it.
  - **Conflict detection is deterministic and deliberately narrow**: contradictory facts sharing a `subject`, supersession forks, claims to supersede something absent, and duplicate active content. Facts without a subject are not compared — deciding whether two arbitrary sentences disagree is a language question, and answering it with a model would make *state acceptance* nondeterministic, which is worse than the LLM-gate objection this project already raised, because the output is the state rather than a report.
  - **Only exact duplicates auto-resolve.** Everything else blocks: silently keeping the newer item is a policy nobody chose and is indistinguishable from having found no conflict. A claim to supersede something missing keeps the item anyway — dropping it loses the fact that a reversal was seen, applying it silently marks nothing.
  - `StructuredExtractor.extract_range` reads part of a session and reports the positions actually read, so a watermark advances to what was read rather than what was requested.
  - 35 new tests, all offline.
- Phase 6. Structured context extraction. Conversation to typed work state, with a validator.
  - `src/open_context/extraction/`: `StructuredExtractor` fills the Phase 1 record types — `Goal`, `Constraint` with hard/soft, `Fact`, `Decision` with a required rationale and alternatives, `Task`, `OpenQuestion`, `Entity`. No record type was added; the model already had them. `Preference`, `Event`, and `Artifact` are deliberately not extracted, because nothing consumes them and a type the prompt names is a type the model will produce whether or not it means anything.
  - **Provenance points at the archive, resolving a question open since Phase 4.** `StateItemBase.sources` speaks SQLite's `msg_`/`ev_` naming and the archive names records its own way, with no correspondence ever established. An `ExtractedItem` carries archive record ids and sequence numbers on the wrapper; `sources` stays empty. Minting `msg_`-shaped ids would assert a link no code maintains, and a reference resolving to nothing is worse than one honestly out of band. An item citing no resolvable source is rejected.
  - **Nothing the model returns is trusted.** Both providers refuse `structured_output`, so JSON is prompted for and parsed defensively: prose and markdown fences stripped, unknown types counted rather than guessed, decisions without rationales rejected, out-of-range confidences clamped, and `true` as a confidence turned into 0.5 rather than maximum certainty — `bool` subclasses `int`, so it would otherwise be the most confident value in the range.
  - **Truncated JSON is never repaired**, and a malformed reply is a recorded failure rather than a silent empty extraction. Guessing at a half-written object is how an extraction invents state, and an empty result and a failed one look identical in a file while meaning opposite things.
  - The model is shown the record ids it must cite. Demanding provenance from a model that was never shown an id, then rejecting every item for citing nothing, would blame it for the harness's omission.
  - Supersession is carried **by content, not by id**: ids are minted after the model has answered, so it could not cite one. Resolving content to an id is Phase 7's.
  - **A deterministic, offline validator that calls no model.** One that asked a model whether the extraction was right would inherit the failure it exists to detect, and make validity nondeterministic at the margin. Errors for wrong session, dangling citation, out-of-range citation, unattributed item, decision without rationale, and everything-superseded; warnings for weak grounding and superseding an unknown item.
  - **It checks grounding, not completeness, and says so.** An extraction that found nothing validates clean — correctly, since it asserts nothing unsupported. Recall is what the Phase 5.5 retention scenarios measure, and conflating them would let an extraction finding one decision in ten score perfectly. `weak_grounding` is word overlap, named as blunt, reported as a warning, and never used to delete anything.
  - Verified against a real model on benchmark scenarios: `reversed-decision` produced both sides of the reversal with rationales, `negative-constraint` produced the prohibition as a hard constraint, both validating clean.
  - Known limits recorded rather than worked around: one model call holds the whole conversation in memory and in the prompt, so a session larger than the context window cannot be extracted; nothing is written to storage; extraction is not incremental. All three wait on Phase 7's supersession and conflict machinery.
  - 44 new tests, all offline.
- Phase 5.8. First real-model benchmark. The machinery to run one against a metered free tier, the run itself, and a failure taxonomy over its results.
  - **Request budget.** `RequestBudget` and `BudgetedProvider` cap how many requests a run may send. The reason is arithmetic: the full matrix is roughly 195 requests and the free tier allows 50 a day, so what happens at request 51 decides whether the run is a measurement or a wreck. Without a ceiling every remaining cell gets a 429 and is recorded as a strategy that was tried and failed; with one, the run stops and the cells nobody asked about are simply absent.
  - **`RequestBudgetExhausted` is deliberately not an `LLMError`.** The runner turns any `LLMError` into a `MODEL_ERROR` result, so if exhaustion were one, the machinery meant to prevent phantom failures would generate them itself. Pinned by a test.
  - Charged before the call, never after: a request that was sent and then failed still consumed quota, so charging on the way out would let a run of failures overspend a budget that reads as untouched. `model_info` is not charged — it answers from configuration and sends nothing.
  - **Pacing, in the harness rather than the provider.** The same tier allows 20 requests a minute. `min_interval_seconds` leaves a gap between requests, measured from the start of the previous one so a slow call already supplies part of it. Nothing catches a 429, backs off, or retries — retry policy stays out of the provider boundary as it has since Phase 4.5, and a 429 that arrives is a real provider failure recorded as one. Off by default, so offline runs are not slowed.
  - **Results are written as they are produced.** `ExperimentRunner.stream` and `stream_benchmark` yield each result; `ResultWriter` flushes each line. A request against a metered tier is not repeatable on demand, and a run that accumulated privately then stopped would discard every measurement it had already bought. `run` and `run_benchmark` are unchanged in behaviour and are now wrappers over the streaming forms.
  - **Resumption that does not re-measure.** `completed_cells` reads a results file back into `(run_id, scenario_id, strategy)` triples; the run id already encodes budget, repetition, model, tokenizer, prompt, and dataset, so a cell from a different budget is never mistaken for one already done. **Only successful cells count as complete** — a rate limit says nothing about a strategy, and treating it as done would freeze a transient outage into the results permanently.
  - `estimated_requests` sizes a matrix before it runs, from a `requests_per_run` declared on each strategy. Documented as a lower bound and tested as one: the Phase 5 compactor chunks and retries, so a run can cost more, and a prediction above the truth would stop a run short of the quota it actually had.
  - **Failure taxonomy** over observed results, in the fifteen classes the roadmap names. A class is a property of an observed failure, not of a scenario: `FailureMode` says which trap a scenario sets, and is used only to disambiguate a failed check whose category alone cannot — a lost constraint and a lost *negative* constraint are both written as constraints.
  - **Three classes are declared and cannot be measured, and report as unmeasured rather than zero.** Nothing detects a lost goal, lost completed work, or irrelevant context that survived; each is listed with what would close it. A zero beside `lost_goal` would assert no goal was lost, which is a claim about the strategies, and the wrong one — a strategy that dropped every goal would produce the same zero.
  - Every failed check lands somewhere: one the mapping cannot label is counted as `unclassified` rather than dropped, so per-class counts and the total agree. A run that ended in a model error contributes nothing — it produced no response, and counting it would turn a provider outage into a finding about a strategy.
  - **`check_comparable` now reports unequal scenario coverage**, which this run needed and did not have. A budget-stopped run leaves the reference arm complete and the compacted arms partway through, and the report then prints one row per arm, each averaging a different subset, lined up in a table that invites exactly the comparison they cannot support. The reference arm is included in every budget's comparison rather than grouped alone at its own budget, which is where the largest gap appears. Unequal `Runs` counts were always visible to a reader who thought to distrust the table; a benchmark that has to be distrusted to be read correctly is leaving the work to the reader.
  - `--max-requests`, `--min-interval`, and `--resume` on `benchmark`; `compare --benchmark` re-reports an existing results file with the per-arm table, taxonomy, and comparability warnings, sending no request — which matters when the run cost a day's quota and the reporting code has since improved.
  - **The run.** Complete matrix: dataset `v3`, budget 160, `groq/llama-3.1-8b-instant`, judged, 45/45 cells with every arm on every scenario, `check_comparable` clean. **The Phase 5 baseline does not beat a plain summary** — identical deterministic scores (0.92 both), worse on judged questions (5/14 against 8/15), and more tokens for the same context size. Phase 5 called itself the control later work has to beat; it has not beaten anything yet, which is what building a control is for.
  - **Compaction cost more than it saved:** 705 tokens end to end for full context against 1222 and 1306 compacted, at 2.5x smaller context. Where that reverses is unmeasured.
  - **What compaction lost was exact values.** Two deterministic failures in the whole matrix, both compacted: a port number among similar ports, and a row count from a tool result. Full context lost neither.
  - **A benchmark's discriminating power depends on the model under test.** An earlier complete matrix on `llama-3.3-70b-versatile` scored 1.00 on everything for every arm — a ceiling effect indistinguishable from a measurement. The 8B model is what made the differences visible.
  - Earlier partial runs against `openrouter/google/gemma-4-26b-a4b-it:free`
  - **Compaction cost more tokens than not compacting.** 706 tokens end to end for full context against 1190 and 1217 for the compacted arms, for a context 3.3–3.8x smaller. The summarization call is not free, and at these conversation sizes it outweighs what it saves. A within-arm comparison, so the unequal sampling does not affect it.
  - **The throttling was not the documented throttling.** The published free-tier limits are 50 requests a day and 20 a minute; the first run lost about a quarter of its requests to 429s at roughly four a minute, from upstream capacity for that specific model. The daily cap arrived separately and named itself. Both are recorded as `model_error` with no metrics, are not counted as complete, and are retried on resume.
  - **A defect in the benchmark, found only because the model was real: eight of the run's ten failure findings are artefacts.** Both halves of the deterministic scorer assert absence by substring — `RetentionCheck.forbidden` and `CompletionCriterion.alternatives` — so a model honouring a negative constraint by naming what it rejected ("Since Redis is explicitly prohibited, I recommend an in-memory cache") fails both, and is additionally counted as a hallucination. All four `lost_negative_constraint` findings and all four "used something the conversation ruled out" findings were manually verified as correct answers; across 27 successful runs the scorer found two genuine losses. Invisible through Phases 5.5 and 5.6, whose fake provider returned one fixed string that never contained a prohibited term. The bias favours compaction over the reference, which collected three of the eight artefacts. A cleverer pattern is not the repair — `RetentionCheck` already documents that the honest answer is a judged question — so the fix is to assert the approach that should have been chosen rather than the word that should not appear, which is a `v3` dataset. `v2` is left unedited, and the repair is recorded as an open question.
  - **Dataset `v3`, the repair.** Built from `v2` by transformation, the way `v2` was built from `v1`; conversations, tasks, and failure-mode tags are `v2`'s verbatim, and a test asserts `v2` and `v1` unchanged. One rule: **deterministic checks assert presence, judged questions assert absence.** Every negative substring assertion is gone — 6 retention checks and 14 completion criteria — and each becomes a `JudgedQuestion`, which reports *not evaluated* without a judge rather than passed or failed. A check keeping a `required` list survives with `forbidden` dropped; one that was only a `forbidden` list is removed rather than emptied, since an empty check always passes.
  - Hedging questions are derived from the criterion they replace, restating its description and naming the exact options removed, so a question cannot drift from what it stood for and a new criterion cannot leave an unreplaced assertion behind. Each tells the judge that naming a rejected option is not a violation — the distinction the substring match could not make.

Without a judge they measure nothing, which is recorded rather than fixed by inventing an expected answer.
  - **What `v3` costs: hedging is no longer caught deterministically.** "Use SQLite or PostgreSQL" now satisfies `reversed-decision`. Accepted rather than papered over — a check that catches hedging and also fails correct answers was not measuring hedging. A judge becomes the gating dependency rather than a refinement.

Versioned `JUDGE_PROMPT_V1`, hashed into the run fingerprint like every other prompt, and it states to the grader that naming a thing purely in order to reject it counts as having avoided it — the distinction the substring checks could not make, told to the one component that can act on it.
  - **A judge that cannot decide says so.** `JudgeVerdict.evaluated` is false when the grading model errored or answered unreadably, and the runner records that as not evaluated rather than as a failure. A guessed NO is indistinguishable from a real one in a results file. The parser reads YES or NO off the first meaningful line, tolerating markdown and punctuation, and refuses to mine a verdict out of prose. `KeywordJudge` with no rule for a question now reports undecided too, where it previously reported a failure.

Pinned by a test. `RequestBudgetExhausted` is deliberately not caught by the judge, since it is not an `LLMError`.

Its bias is uncharacterised; it is nondeterministic at temperature zero and may be the model under test, so `LLMJudge.name` carries the provider and model into the fingerprint rather than the configuration being refused.

- Phase 5.7. Real model provider layer. The first implementations behind the Phase 4.5 boundary; **no benchmark was run against a real model and no result is claimed**.
  - `GroqProvider` and `OpenRouterProvider` implementing `LLMProvider` as Phase 4.5 wrote it. The interface did not change, and no second provider architecture was introduced.
  - **No dependency was added.** Both post JSON over `urllib`; an SDK per vendor is a large surface for a small benefit, and the base package keeps its single runtime dependency. They share a wire dialect through a private helper both call — shared implementation, not a second abstraction — and each owns its own name, credential, endpoint, headers, and defaults.
  - Transport is injectable, so provider tests exercise the real request translation and error mapping against canned responses without opening a socket. The default suite still runs with no key, no network, and no model server.
  - `open_context.llm.free_models`: an explicit allowlist of models the benchmark may call, each entry recording the date its price was read as zero and the endpoint it was read from. **A credential is not evidence of price** — Groq's key reaches a dozen priced models, OpenRouter's reaches hundreds of which a handful are free.
  - **Validation runs in the provider constructor, before the credential is read**, so an unapproved model costs zero HTTP requests and zero money. Proven by a counting transport rather than asserted. A `:free` suffix is never consulted: it is a naming convention, conventions drift, and a model that stopped being free would keep its name.
  - **No paid fallback, and no fallback mechanism at all.** A free model that is unavailable, rate-limited, over quota, timing out, or erroring fails. Choosing another approved free model is the caller's explicit act; a test asserts no such machinery exists. `billing_class_of` returns `UNKNOWN` for anything unapproved, never `FREE` by default.
  - **No Groq model is approved, and that is a finding rather than an omission.** Groq prices every chat model it serves; its free tier is an account-level allowance against priced models, and nothing in the API distinguishes "within my allowance" from "billed". The provider implementation works; the policy is what stops it.
  - Provider-neutral error translation for 401/403, 429 with `retry_after`, 404, 400/422 including context overflow recognised from the provider's own error text, 5xx, and no response at all. **No retries**: `retry_after` is carried, never acted on, keeping retry policy out of the provider boundary as it has been since Phase 4.5.
  - `structured_output` raises `UnsupportedCapabilityError` on both, and neither advertises the capability. Both services expose a JSON mode, but whether a given model honours a schema varies and OpenRouter routes to many models, so the flag would be right for some routes and wrong for others.
  - **No model is hard-coded and no context window is invented.** The model is always the caller's, the result records the identifier the service actually served, and `ModelInfo.context_window` is whatever was configured explicitly and `None` otherwise. A missing credential is an error, never a quiet fall back to the fake — a real-model run that silently became a deterministic one would produce numbers labelled as measurements.
  - Credentials travel in the `Authorization` header and nowhere else: not the URL, not the body, not `repr`, not any error, not any serialized result. `HttpRequest.redacted_headers()` is the only sanctioned way to render a request, and tests use a placeholder.
  - Smoke test, opt-in and marked `llm`, run 2026-08-13: five of six approved OpenRouter models generated through the ordinary interface; `google/gemma-4-31b-it:free` returned 429 and was recorded as rate-limited rather than substituted; Groq skipped for having no approved model. All six were re-confirmed at zero prompt and completion price before any request was sent.
  - 83 tests across `test_llm_providers.py`, `test_free_models.py`, and the smoke test, plus a boundary-test extension asserting `llm/providers` is the only package that may import a network module. All but the smoke test are offline and need no credential.
- Phase 5.6. First benchmark. Infrastructure and a deterministic run; **no real-model result was produced and none is claimed**.
  - Benchmark matrix of scenarios x strategies x budgets x repetitions, orchestrating the Phase 5.5 `ExperimentRunner` rather than replacing it, so leakage prevention, the same-prompt guarantee, and the run fingerprint come from already-reviewed code. Each budget and repetition is its own run with its own `run_id`.
  - **Task completion**, the metric Phase 5.5 deliberately left unmeasured, reported separately from retention and never averaged with it. Criteria are conjunctive and discriminating: the right answer must be present *and* the options the conversation ruled out absent, with a substance floor, so hedging across every remembered option fails. Criteria needing code execution report `not_evaluable` and are excluded from the denominator rather than counted as failures.
  - Dataset `v2`: `v1` scenarios with completion criteria attached and three failure-mode tags added. `v1` is not edited, and a test asserts its conversations, tasks, and retention checks are unchanged. Coverage of all seventeen named failure modes is enforced by test.
  - Cost accounting split between compaction and continuation — tokens, calls, and latency each — so a small context bought with many model calls is not compared as though compaction were free. Unreported usage is `None`, never zero.
  - `evaluation_mode` on every result and in the fingerprint, so a fake-provider run and a real-model run are never filed under one identity, and every deterministic report says at the top that it measures the harness.
  - `check_comparable` names any results set spanning more than one model, prompt, dataset version, or evaluation mode, rather than presenting it silently as a fair comparison.
  - Budgets 80/160/240, chosen below every scenario so compaction actually happens; full context is an unbudgeted reference, since truncating it would make the reference a different strategy.
  - **The reference arm is budget-independent and runs once per scenario and repetition**, not once per budget. Running it per budget would take independent samples of one condition and average them into a row labelled budget-independent — against a real model, three draws wearing one label. Budget independence is declared on the strategy rather than listed in the orchestrator, a reference result records `target_tokens = 0` because it consulted no budget, and every budget row is compared against the same reference population. The matrix is `scenarios x repetitions x (references + compacted x budgets)`: 105 runs by default, as 15 / 45 / 45.
  - `python -m open_context_eval benchmark`, with a failure report that names which check failed on which scenario for which strategy. Artifacts under git-ignored `benchmarks/`.
  - Result format version 4. 64 new tests, all offline.
- Phase 5.5. Evaluation harness. Infrastructure only; no result is measured or claimed.
  - `open_context_eval`, a package beside the runtime rather than inside it: it imports `open_context`, is never imported by it, and is excluded from the distributed wheel. The dependency direction is checked by a test that parses every runtime module.
  - Measures **downstream task continuation, not summary quality**. Every arm runs the same task through the same model with the same prompt and budget; only the context representation varies.
  - `EvaluationScenario` pairs a conversation with the task the next agent must perform, plus deterministic checks and judged questions that only the evaluator sees. Six task kinds, extensible without touching the runner.
  - Leakage prevented structurally: `build_continuation_request` takes two strings and has no access to a scenario or an archive, so neither an expected answer nor a removed conversation can reach a model. The downstream prompt is asserted to be exactly context plus task, and never names the strategy under test.
  - Three arms: `full_context`, which reports itself unavailable rather than truncating when the conversation exceeds the model's window; `simple_summary_v1`, a plain-summarization baseline that is one LLM call plus deterministic budget enforcement and shares no compaction logic with Phase 5; and `phase_5_baseline`, the Phase 5 compactor called through its public interface and not modified. Retrieval and MemHandoff are absent rather than stubbed.
  - **Deterministic retention checks**, named so they are not mistaken for task completion. They ask whether an expected fact, constraint, or decision survived into the response; whether the agent continued the work well is a different question and is unmeasured. There is deliberately no `task_completion` category, and no threshold for "almost as effectively as full context" is chosen. Provenance and hallucination are declared and unimplemented. `EvaluationJudge` is a seam with a deterministic stand-in — a judged question with no judge is reported as not evaluated, never as passed or failed.
  - Scenario materialization is idempotent and content-addressed, so repeating an experiment against one archive root cannot silently double the conversation. A session holding anything else raises rather than being appended to.
  - `run_id` hashes a canonical serialisation of everything that can change a result — dataset, scenarios, provider, model, context window, tokenizer identity and exactness, budgets, prompt identity and hash, strategy names, versions, and per-strategy configuration — and nothing that cannot. The fingerprint is computed once and both hashed into `run_id` and persisted on every result as `RunMetadata.fingerprint`, so a stored result is self-describing and re-hashes to confirm its own identity. The named convenience fields are read out of it and validated against it, so nothing stored can contradict the identity it contributed to.
  - Versioned synthetic dataset `v1`: 15 scenarios covering early and late critical facts, buried facts, negative constraints, reversed decisions, failed approaches, exact values, confusable entities and numbers, temporal state, tool results, open tasks, rationale, multi-step work, and repeated misinformation. A run refuses to mix dataset versions.
  - Results as JSON Lines, each line independently interpretable and carrying full run metadata. `run_id` is derived from the experiment rather than the clock, so the same experiment reproduces its identity on any machine.
  - Failures are never zeros: six statuses, and a failed run carries `None` metrics so a broken experiment cannot read as a bad strategy. Reports print status instead of a number and list failures separately.
  - `python -m open_context_eval list-scenarios | run | compare`. A module runner rather than a console script, so the project's unresolved CLI naming question is not answered by accident.
  - 117 new tests, all offline: no key, no network, no model server, no database.
- Phase 5. Baseline compaction engine. A baseline intended for measurement, not the final MemHandoff algorithm.
  - `BaselineRecentPlusSummary`: summarize the older part of a session through `LLMProvider`, keep the most recent part verbatim, hold the result to a measured token budget. `CompactionStrategy` is a three-member protocol so a second strategy is a second class; there is no factory or plugin loader.
  - Budget allocated by a fixed configurable fraction, default 60% summary and 40% recent, reported on every result. Targets below a configurable minimum raise `TargetTooSmallError` rather than returning something misleading.
  - Recent window selected by token budget, not message count, walking backward with positional reads so the archive is never scanned to find it. Whole events only; an event larger than the entire recent budget leaves the window empty and is summarized instead, with a warning.
  - The model's word is never trusted: the summary is tokenized against its budget, retried once at a smaller size, then cut deterministically at a word boundary with a visible marker counted inside the budget.
  - Final budget enforcement preserves the recent window and reduces the summary. The two halves cover disjoint archive ranges, so an event in the window is not condensed into the summary and dropping one removes it from the output entirely; recent-event dropping is therefore an emergency branch reached only if the window alone exceeds the target, which allocation prevents. When taken it records `recent_events_dropped`, an explicit information-loss warning, and `dropped_recent_event_count`, and `historical_range` keeps reporting what was actually summarized so the gap between the ranges shows exactly what was lost.
  - Context-window aware: history is chunked to fit `ModelInfo.context_window`, with a two-level chunk-then-combine pass recorded as `multi_pass_summary`. An unknown window is reported as a warning, never assumed.
  - A conversation already within target is returned whole with no model call, which is also the full-context control case a benchmark needs.
  - Versioned prompt `BASELINE_SUMMARY_V1`, with a content hash on every result so a benchmark can tell the prompt changed underneath it.
  - Result carries strategy, version, prompt id and hash, configuration, all four token counts with their `exact` flags, archive ranges, recent event ids, fallbacks, warnings, tokenizer and model identity, LLM call count, and compression and retention ratios — neither of which is a quality measure.
  - Produces no structured state: no `Decision`, `Goal`, or `Task`, and nothing is written to SQLite. The result is an internal experimental representation, not `.ctx` and not a portable package.
  - The archive is never modified, pinned by hashing every file in the session directory before and after compaction, including after a failed one.
  - 71 new tests, all offline and deterministic against the Phase 4.5 fakes. The boundary test now also covers compaction, so the first consumer of the LLM abstraction cannot shortcut it.
- Phase 4.5. LLM provider and tokenizer abstraction. No compaction, summarization, extraction, retrieval, or context-pressure detection.
  - `LLMProvider` protocol: `model_info`, `generate`, `structured_output`. `GenerationRequest` carries only knobs that mean the same thing everywhere; provider-specific settings go in `options`. `GenerationResult` keeps the provider response as parsed, alongside provider-reported `TokenUsage`, which is never filled in from an estimate.
  - `Tokenizer` protocol, separate from providers because not every provider can count what it generates. `TokenCount(count, exact, method)` with the invariant that an estimate is never presented as exact — enforced by arithmetic, since adding an exact count to an estimate yields an estimate. Three states ship: exact, `CharacterRatioTokenizer` which is never exact, and `UnavailableTokenizer` which raises rather than guessing.
  - `ModelInfo` with a `Capability` set, and `None` rather than an invented number for an unknown context window. No `STREAMING` capability: the interface exposes no streaming method, so the flag would have been a claim a caller could not act on. Streaming is recorded as a future capability, method and flag together.
  - Provider-neutral errors under `LLMError`, covering authentication, model unavailable, invalid request, rate limit, context limit, provider unavailable, malformed structured output, tokenization unavailable, and unsupported capability. Implementations translate vendor exceptions into these; none may escape.
  - Structured output normalized around JSON Schema, with `schema_for` for pydantic models. `parse_structured_output` checks top-level shape only, and that limit is documented and pinned by a test rather than implied.
  - `ProviderConfig`, environment loading under `OPEN_CONTEXT_`, and a name-based registry so a provider needing an optional dependency is available when installed and absent when not. `api_key` is excluded from `repr`.
  - Deterministic `FakeProvider`, `FailingProvider`, and `WordTokenizer` ship in the package, so later phases and downstream users have an offline provider. No real provider was implemented: no vendor API could be verified from this environment, and the registry makes adding one additive.
  - The dependency direction is enforced by tests that read the source: the core never imports the LLM layer, the LLM layer never imports the core, and no package imports a vendor SDK, a network module, or a subprocess module.
  - 85 new tests, all offline and requiring no credentials. `pydantic` remains the only runtime dependency.
- Phase 4.1. Four corrections to Phase 4, no new capability.
  - Synthetic archive ids are now scoped to a logical source, not to the import run. `synth-<fingerprint of the source key>-<position>`. A second import into the same session previously reused `pos-00000000` for its first unidentified event, which the archive reads as the same item written twice.
  - Source identity, content digest, archive sequence, and synthetic event id are now four separate concepts in the import layer. Source identity is a caller's judgement and not derivable from bytes: two byte-identical exports may be one logical source or two. An intermediate version of this correction used the content digest as the source key and so silently merged identical files.
  - `import_events` requires an explicit `source_key`; `import_path` accepts one and otherwise defaults to `default_source_key(path)`, documented as "this file, holding this content, at this location". `ImportReport.source_key` reports which identity was used. `content_digest_for_path`/`_bytes` fingerprint content, `source_key_fingerprint` encodes an identity into an id.
  - Synthetic ids are deterministic and collision-resistant for distinct logical source keys — a truncated SHA-256, described as such rather than as guaranteed unique.
  - Import atomicity resolved explicitly as non-atomic, since the archive has no delete, truncate, or rollback. A failure now raises `IncompleteImportError` carrying an `ImportReport` with `completed=False`, `events_written`, and `last_seq`, so a caller learns exactly what is on disk. `MalformedRecordError` and `DuplicateSourceIdError` derive from it. The record that caused the failure is never written. `ImportReport.clean` is false for any partial import.
  - Policy value `"error"` renamed to `"abort"` on both `on_malformed` and `on_duplicate`, because stopping a running import is what it does.
  - `role="tool"` still maps to `TOOL_RESULT` and is now documented as a generic convention rather than a provider fact; a provider adapter must classify tool events from its own verified format and not inherit it.
  - `raw` is described as "the provider record as parsed, with unknown fields preserved" throughout, replacing wording that implied byte-level preservation of the source. No field is dropped; representation is not kept, and that is now stated and tested.
  - 26 new tests.
- Phase 4. Conversation import adapters.
  - `RawEvent`, the provider-neutral normalized event: seven event kinds whose message roles mirror `models.enums.Role`, plus source id, source type, timestamp, text, tool identity, parent reference, and the provider's own record in `raw`.
  - `ConversationImporter` protocol. An adapter knows one transport format and nothing else; opening files, session ids, archive writes, error policy, and counting are the pipeline's. `read` yields `RawEvent | MalformedRecord` rather than raising, so a failure is a value that cannot be dropped by accident and a bad record does not kill the generator.
  - `JsonLinesImporter`, the generic adapter: one JSON object per line, configurable `FieldMap` and role mapping, no provider-specific branch anywhere. A top-level JSON array is deliberately unsupported, because `json.load` would buffer the whole document.
  - Streaming pipeline: `import_path`, `import_events`, `stream_events`, one event held at a time, verified with `tracemalloc` against a 4MB source.
  - `ImportReport` with exact counts and capped samples for malformed records, duplicate ids, missing and unusable timestamps, unrecognised event kinds, and unmatched tool results. Nothing is discarded silently and no timestamp or identity is invented.
  - Archive `kind` is the event type, and an event with no source id gets a deterministic `pos-<position>` record id, so importing one file twice produces identical identifiers.
  - Import writes the archive and nothing else. No state item, no evidence, and no message row: "We should use PostgreSQL" stays a message and does not become a `Decision`.
  - 91 new tests. No Claude, Codex, or Gemini adapter: their transcript formats were not available to verify, and are recorded as open questions rather than guessed at.
- Phase 3.1. Two corrections to Phase 3, no new functionality.
  - `Archive.open` now checks that the manifest's `session_id` matches the session asked for, and raises the new `ManifestMismatchError` when it does not. A copied or renamed session directory would otherwise attribute one session's conversation to another. Format and version are still checked first. 4 new tests.
  - Two invariants documented rather than implemented: a `SessionLog` has a single writer and concurrent writes to the same session are unsupported in Phase 3; the data file is the durability boundary, the index is derived data that may lag, and recovery rebuilds it from the data file. No lock, writer process, or queue was added — Phase 4 decides the write-coordination model once agent adapters exist.
- Phase 3. Local immutable archive.
  - Append-only JSONL on the filesystem, one log per session, with a manifest and a rebuildable 12-byte-per-record offset index.
  - Per-record sha256 over canonical JSON, byte-exact with no Unicode normalisation, so corruption in a stored original is always detected.
  - Streaming reads throughout: `read`, `range`, `window`, `tail`, iteration, and `verify` all hold one record at a time. No read-everything API exists.
  - Bounded tail recovery on open. A torn or unparseable final record is truncated and reported; damage elsewhere raises rather than being repaired.
  - Data file is synced before its index entry, so the crash window is always repairable from the data file.
  - 55 new tests, including `tracemalloc` assertions that peak memory does not scale with archive size.

### Changed

- Product realignment. Documentation only; no code, model, or schema change.
  - The product is a portable context package for agent handoff, not a general context runtime or memory system. Added `docs/product-architecture.md`.
  - Three layers made explicit throughout: raw conversation, portable package, agent-specific context.
  - Roadmap rewritten. Evaluation moved to Phases 5.5 and 5.6, directly after the baseline compactor. Provider and tokenizer abstraction moved from Phase 16 to 4.5. Package format became Phase 9, ahead of the compiler.
  - Cross-session memory backends, paging, and the standalone MCP phase dropped. MCP returns as one adapter in Phase 11.
  - Three conflicts recorded between the existing implementation and the new direction: cross-machine provenance versus referential integrity, whole-result-set reads versus the RAM constraint, and `ContextSnapshot` not being a portable package.

### Fixed

- Phase 2.1. Storage integrity corrections.
  - Migrations are now atomic. `executescript` issued an implicit COMMIT before running, so a failing migration left its completed statements permanently applied. Each migration now runs as individually split statements inside one explicit transaction.
  - Every reference is now checked for session locality; `CrossSessionReferenceError` added.
  - A supersession cycle within a single batch is now rejected; `SupersessionCycleError` added.
  - The `raw source -> evidence -> state` provenance layering is documented and pinned by tests. No schema change was required.
  - 28 new tests. No change to the Phase 1 data model or the database schema.
